# painhubproxy для десктопа

Приложение для Windows, которое поднимает MTProto-прокси на компьютере и отдаёт его
в локальную сеть. Телефон (iPhone или Android) в той же Wi-Fi подключается к
`192.168.x.x:1443` по обычной `tg://proxy`-ссылке. Живёт в области уведомлений,
окна не имеет.

Это не VPN и не системный прокси: остальной трафик машины никуда не заворачивается.

## Зачем это нужно

Основное приложение — Android-клиент с локальным listener на `127.0.0.1`. iOS такого
не умеет: система не даёт обычному приложению держать локальный порт в фоне. Десктопная
версия решает это иначе — прокси живёт на компьютере, а телефон обращается к нему по
локальной сети. Telegram подключается нативно, без сторонних клиентов.

Ограничение: оба устройства должны быть в одной сети. Ушли с Wi-Fi — прокси недоступен.

## Сборка

Нужен Rust с тем же тулчейном, что и для Android (`rust-toolchain.toml`), и на Windows
хост-сборка идёт через GNU-тулчейн: MSVC-линкер в типовой установке отсутствует.

```powershell
.\scripts\build-desktop.ps1
```

Готовый файл: `dist\painhubproxy-desktop.exe`.

Вручную:

```powershell
cargo build -p painhubproxy-desktop --release
```

Windows-сборка не открывает консольное окно (`windows_subsystem = "windows"`), поэтому
все сообщения идут в журнал, а не на экран.

## Где лежат файлы

| Файл | Путь |
|---|---|
| Настройки | `%APPDATA%\painhubproxy\config.json` |
| Журнал | `%APPDATA%\painhubproxy\proxy.log` |

Журнал ротируется при превышении 4 МБ в `proxy.log.1`.

## Настройки

```json
{
  "port": 1443,
  "host": "0.0.0.0",
  "link_ip": "192.168.1.138",
  "secret": "39cecaabe8a212ad9b63c760a3cb12ba",
  "extra_args": "--default-domains --cf-balance --pinned-upstream cfproxy --cf-disable-tls",
  "autostart": false,
  "verbose": false
}
```

- `host` — `0.0.0.0`, иначе телефоны не достучатся.
- `link_ip` — адрес, который попадёт в ссылку. Пустое значение означает «определить
  автоматически»: берётся адрес интерфейса, через который машина выходит в сеть.
  Если в системе несколько сетей, укажите адрес Wi-Fi вручную.
- `secret` — 32 hex-символа. Создаётся при первом запуске и больше не меняется:
  Telegram хранит прокси по полной ссылке, и новый секрет на каждый старт ломал бы
  уже добавленную запись (каждая сессия гасилась бы как `bad handshake`).
- `extra_args` — всё остальное уходит в ядро как есть. Здесь остаются доступными
  любые флаги `tg-ws-proxy-rs`, без отдельных полей в интерфейсе.
- `verbose` — уровень `debug` вместо `info` в журнале.

Настройки читаются один раз при старте: после правки `config.json` приложение нужно
перезапустить.

### Про `--cf-disable-tls`

Значение по умолчанию собрано под сеть, в которой TLS к `kws*.web.telegram.org`
блокируется по SNI: Cloudflare-маршрут достигается по `ws://` на порту 80, без TLS.

В незаблокированной сети это лишнее — уберите `--cf-disable-tls`, и трафик пойдёт по
`wss://`. Проверить просто: если `curl -I https://kws2.web.telegram.org` отвечает,
флаг не нужен.

## Меню в области уведомлений

| Пункт | Действие |
|---|---|
| статус | состояние и адрес вида `192.168.1.138:1443` |
| Копировать ссылку | кладёт `tg://proxy?...` в буфер обмена |
| Открыть в Telegram | передаёт ссылку системе, Telegram предложит подключить прокси |
| Запустить / Остановить | останавливает и поднимает ядро без перезапуска приложения |
| Перезапустить | полезно после смены сети |
| Открыть журнал | `proxy.log` в блокноте |
| Открыть настройки | `config.json` |
| Автозапуск при входе | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` |
| Выход | останавливает прокси и завершает процесс |

Левый клик по значку открывает ссылку в Telegram, правый — меню.

## Подключение телефона

1. Убедиться, что телефон и компьютер в одной Wi-Fi.
2. В меню выбрать «Копировать ссылку» (или открыть в Telegram прямо с компьютера).
3. Отправить ссылку себе в Telegram и открыть на телефоне — либо ввести вручную:
   Настройки → Данные и память → Прокси → MTProto.
4. Проверить: Safari/Chrome на телефоне должен открывать сайты **напрямую**, не через
   прокси — прокси прописан только внутри Telegram.

Если телефон не подключается:

- проверьте, что в ссылке адрес Wi-Fi, а не `127.0.0.1`;
- на компьютере: `netstat -ano | findstr :1443` — должен быть `0.0.0.0:1443 LISTENING`;
- брандмауэр Windows может спросить разрешение для `painhubproxy.exe` — нужно разрешить
  для частных сетей;
- если порт занят другим приложением, смените `port` в настройках.

## Ограничения

- Только Windows проверялся в работе. Linux и macOS собираются (ветки `cfg(not(windows))`),
  но автозапуск там не реализован, а значок и меню требуют рабочего окружения.
- Секрет лежит в `config.json` открытым текстом. Для прокси в локальной сети это
  приемлемо; для публичного адреса нужен другой подход.
- Список Cloudflare-доменов по умолчанию публичный. Для постоянного использования
  поднимите свой Worker — см. [CfWorker.md](CfWorker.md).
- `--cf-disable-tls` означает передачу без шифрования до Cloudflare: обфускация MTProto
  на проводе различима. Это вынужденная мера для сетей с фильтрацией SNI.
